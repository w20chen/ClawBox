# Deployment manifests

Production manifests in this directory implement only the ARM64 Firecracker path.

Apply in this order after the host gate passes:

```bash
kubectl apply -f deploy/runtimeclass-firecracker.yaml
kubectl apply -f deploy/sandboxtask-crd.yaml
kubectl apply -f deploy/control-plane-rbac.yaml
kubectl apply -f deploy/trace-ingester.yaml
python3 scripts/collect-node-capacity.py --configmap | kubectl apply -f -
kubectl apply -f deploy/cell-controller.yaml
```

Before applying, replace every `registry.example.com` image reference. The controller intentionally has one replica because CR status reservations serialize whole-Cell admission.

Required Secrets:

- `clawbox-system/clawbox-control-plane`: `database-url`, `service-token`, `ingest-secret`;
- `clawbox-benchmarks/clawbox-llm`: `llm-api-key`, `llm-upstream-base-url`, `llm-model`, `openclaw-model-ref`.

Templates are `control-plane-secret.example.yaml` and `swe-rebench-secret.example.yaml`; replace every placeholder before applying them.

The task-scoped SSH and upload Secret is generated by the controller. Its Tool volume projection excludes the client private key and upload token; its Runtime projection excludes the Tool host private key.

`cell.yaml` is a render-only `SandboxTask` example. `cell.sh` substitutes the task ID, immutable ARM64 digest, LLM Secret, egress CIDR, profile, and timeouts. Child Pods are never authored directly by operators.

`containerd-firecracker.toml` is installed by the devmapper script only after artifact audit. It is not a standalone manifest and must not be copied before the thin pool name and Kata ConfigPath have been validated.
